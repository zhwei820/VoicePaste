# VoicePaste

把「微信输入法语音输入」变成**干净、只出现一次**的文字，并自动粘贴到当前焦点窗口。

专治：在 WSL / 终端 / 某些编辑器里用微信语音输入时，识别文字被「双写」重复的问题。

---

## 它解决什么问题

微信输入法的语音输入（按住它在微信输入法里设置的语音快捷键说话，例如 `Win+Alt`）会把识别结果通过 IME 直接上屏到当前焦点窗口。
在终端这类会自行回显输入的地方，文字就被插入两遍：

```
我想问一下这个问题我想问一下这个问题
```

VoicePaste 的做法是：**把语音文字先接进一个临时捕获框，再干净地粘贴一次到原来的窗口**，于是只剩一份。

## 工作原理

1. 你按住语音热键说话时，程序：
   - 记住当前前台窗口（也就是你想粘贴进去的那个窗口）；
   - 立刻把焦点切到一个几乎不可见、但真实可聚焦的捕获文本框；
   - 不拦截、不模拟任何按键 —— 微信输入法自己响应你的真实按键（实测它会忽略程序伪造的按键）。
2. 你松开热键后，微信识别完成，通过 IME 上屏 —— 文字进入的是**捕获框**而不是终端，所以不会被回显两次。
3. 程序轮询捕获框，等文字停止增长（默认 600ms）后判定识别结束：
   - 读取整段文字 → 写入剪贴板；
   - 切回原来的窗口 → 发送 `Ctrl+V` 粘贴（可关闭，改为仅放剪贴板）。
4. 清空并隐藏捕获框，等待下一次说话。

整个过程对外表现就是：**照常用热键说话，文字干净地出现一次在原窗口。**

## 功能特性

- **去重复写**：语音文字不再在终端 / 编辑器中重复一遍。
- **任意窗口可用**：Word、浏览器、聊天框、WSL 终端、VS Code 等，只要能粘贴就行。
- **开始菜单/搜索守卫**：`Win+Alt` 里的 Win 键会让 Windows 顺带弹出「开始菜单/搜索」，
  有时抢走焦点，语音文字就上屏到搜索框里去了（表现为「文字跑到 Windows 里去」）。
  程序在说话、等识别、粘贴期间盯着这些窗口，一出现就关掉并把焦点抢回捕获框；
  如果按热键时前台已经是搜索框，会改用「上一个真实窗口」作为粘贴目标（`close_start_menu`）。
- **自动粘贴**：松键、识别结束后自动回到原窗口粘贴；也可设为只放剪贴板手动粘贴。
- **可自定义热键**：程序热键必须**和微信输入法里设置的语音快捷键完全一致**（默认 `Win+Alt`）。
  - `talk_hotkey`：程序监听的语音热键（说话用）；
  - `voice_trigger_hotkey`：微信输入法里的语音快捷键，两者相同即进入透传模式（不注入按键）。
- **低层键盘钩子**：能识别左右 Shift / Win / Ctrl / Alt，支持组合键；并自动忽略程序自己注入的按键，避免误触发。
- **可靠的焦点切换**：用 `AttachThreadInput` + `SetForegroundWindow` 强制前台并聚焦捕获框，粘贴前同样强制切回目标窗口。
- **智能结束判定**：文字停止增长达到 `commit_delay_ms` 即粘贴；松键后 `no_text_timeout_ms`（默认 15 秒）仍无文字则超时收尾并给出提示。
- **剪贴板可选恢复**：可配置粘贴后恢复剪贴板原有内容（默认关闭）。
- **能读到 IME 合成串**：微信语音的结果先写在 IME 合成串里（`TextBox.Text` 看不到），程序用 `ImmGetCompositionString` 读取。
- **调试日志**：同目录 `voicepaste.log`；`debug=true` 可打印捕获文字的变化细节。
- **单实例**：启动时自动终止同名的残留进程。
- **零依赖**：纯 .NET Framework + WinForms，无第三方库，编译为独立 exe。
- **后台常驻 + 托盘图标**：没有控制台窗口，右键托盘图标可查看日志、配置文件或退出。
- **键盘钩子自愈**：Windows 在低层钩子回调超时后会**静默卸载**钩子（表现就是热键突然完全没反应、
  微信语音直接接管）。程序每 5 秒主动重装一次钩子，并重新同步物理按键状态，避免“卡在说话中”
  导致后续热键全部失效。
  早先是用「每秒注入一个 F24」来探测钩子死活，但注入的按键同样被系统算作**用户输入**：
  屏幕刚熄灭就被它点亮，还会让电源计划的「几分钟后关闭显示器」永远不生效 —— 已改掉。
- **息屏热键**：可选（`screen_off_hotkey=Alt+L`）。按 `Alt+L` 不锁屏，而是直接关显示器；
  动一下鼠标或按任意键就亮屏，回到原来的桌面（不用输密码）。适合「只想快点黑屏走开」，
  代价是**不锁屏**，公共环境或带敏感数据的电脑慎用。

## 使用方法

### 运行

双击 `VoicePaste.exe`（或从命令行启动）即可。

程序在**后台运行，没有控制台窗口**，启动后会弹一次气泡提示，并在通知区域（托盘）
显示一个图标。右键该图标可以：

- 查看运行状态（当前热键）；
- 打开 `voicepaste.log`；
- 打开 `voicepaste.conf`；
- 退出 VoicePaste。

然后正常使用微信输入法语音：**按住 `Win+Alt` 说话 → 松开 → 文字自动出现在原窗口。**

> 注意：`talk_hotkey` 必须**等于**微信输入法里的语音快捷键，程序才能接到结果。
> 如果微信输入法里的语音快捷键不是 `Win+Alt`，请把 conf 里两行都改成一致的组合。
>
> 想让程序用 `Shift+Alt`？可以，但 `Alt+Shift` 是 Windows 的“切换输入法”热键，
> 需要先在「设置 → 时间和语言 → 输入 → 高级键盘设置 → 输入语言热键」里关掉它，
> 再把微信输入法的语音快捷键和 conf 里两行都改成 `Shift+Alt`。

### 开机自启

双击 `install-autostart.bat` 即可（会在「启动」文件夹里创建一个 `VoicePaste.lnk`，
登录 Windows 后自动在后台运行，托盘出现图标）：

```bat
install-autostart.bat
```

取消：双击 `uninstall-autostart.bat`（或直接删除
`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\VoicePaste.lnk`）。

> 注意：自启的是当前目录下的 `VoicePaste.exe`。如果以后把文件夹挪走，
> 需要重新运行一次 `install-autostart.bat`。

### 配置

编辑同目录下的 `voicepaste.conf`（`key=value` 格式，`#` 开头为注释），**修改后需重启程序生效**：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `talk_hotkey` | `Win+Alt` | 程序监听的语音热键（按住它说话、松开自动粘贴） |
| `voice_trigger_hotkey` | `Win+Alt` | 微信输入法里的语音快捷键，必须与上一行相同 |
| `no_text_timeout_ms` | `15000` | 松键后多久没有文字就判定失败 |
| `commit_delay_ms` | `600` | 捕获框文字停止增长多久后判定识别结束并粘贴 |
| `paste_on_finish` | `true` | `false` 时只把文字放进剪贴板，不自动粘贴 |
| `restore_clipboard` | `false` | 粘贴后是否恢复剪贴板原内容 |
| `close_start_menu` | `true` | 自动关闭 Win 键带出的「开始菜单/搜索」，避免语音文字上屏到搜索框 |
| `screen_off_hotkey` | 空 | 息屏热键，例如 `Alt+L`：按它只关显示器、不锁屏（本仓库的 conf 已开启）；留空 = 关闭该功能 |
| `debug` | `false` | 打印捕获框文字变化等细节，便于排查 |
| `debug_keys` | `false` | 打印每一个按键事件（排查热键用；会产生大量日志，排完请改回 `false`） |

热键写法：修饰键 `Ctrl` / `Alt` / `Shift` / `Win` 用 `+` 连接，可带一个主键，
例如 `Shift+Alt`、`Ctrl+Alt+V`、`F9`。

### 息屏热键：Alt+L（只息屏，不锁屏）

`voicepaste.conf` 里设了 `screen_off_hotkey=Alt+L`，按 `Alt+L` 就**不会锁屏**，
而是直接关掉显示器；动一下鼠标或按任意键立刻亮屏，回到原来的桌面，不用输密码。
（托盘菜单里还有一项「关闭显示器（测试）」，不用按热键也能试。）

想换组合就改这一行（例如 `Ctrl+Alt+L`），留空则关闭该功能；改完要重启程序。

实现要点（都在 `VoicePaste.cs` 里）：

- 在低层键盘钩子里把组合键的主键（`L`）的按下/松开都吞掉：既不会往文档里打出 `l`，
  也不会触发应用自己的 `Alt+L` 菜单快捷键；
- 如果组合里含 `Win`（旧版用的 `Win+L` 也能用），吞掉 `L` 后 winlogon 收不到它，
  锁屏就不会发生。但 `Win` 的松开也必须特殊处理：直接放行会把刚关掉的屏幕唤醒、
  还会弹出开始菜单；只吞不放又会让 Win 键卡住（之后按键全变 Win+X）。所以程序会
  吞掉 `Win` 松开，先注入一个无副作用的 `VK_NONAME`、再补发「注入的 Win 松开」；
- 程序空闲时**不注入任何按键**（钩子自愈也改成直接重装，不再用 F24 探活），
  所以息屏后不会被它自己点亮；
- 等组合键**全部松开**约 250ms 后，用
  `SendMessage(HWND_BROADCAST, WM_SYSCOMMAND, SC_MONITORPOWER, 2)` 关闭显示器。
  只关屏、不进睡眠，所以唤醒是瞬时的（等待是为了让残留的按键事件先处理完，
  否则一关屏就被它们唤醒）；
- 前台是**管理员权限**窗口时，Windows 的 UIPI 会拦掉注入的按键，程序会退化为
  「放行 Win 松开」并在日志里记一条，不会把 Win 键卡死。

> ⚠️ 不锁屏 = 离开座位时电脑不设防（别人动一下鼠标就能接着用）。公共环境请把
> `screen_off_hotkey` 留空。此时 `Win+L` 仍是系统默认锁屏，但 Windows 默认锁屏后要等
> 1 分钟才关屏；想「一锁屏就黑屏」，把「控制台锁定显示关闭超时」`VIDEOCONLOCK` 调成 1 秒：
>
> ```bat
> powercfg -setacvalueindex SCHEME_CURRENT SUB_VIDEO VIDEOCONLOCK 1
> powercfg -setdcvalueindex SCHEME_CURRENT SUB_VIDEO VIDEOCONLOCK 1
> powercfg -setactive SCHEME_CURRENT
> ```
>

### 编译

推荐直接用 `build.bat`（自动定位 `csc.exe`，编译成功后才替换旧 exe，程序在运行时自动先结束进程）：

```bat
build.bat            :: Release 版，自动结束运行中的 VoicePaste.exe
build.bat nokill     :: 不结束进程（程序在跑时只生成 VoicePaste.build.exe）
build.bat debug      :: 不优化编译
```

PowerShell 里用 `.\build.bat`。也可以手动调用 Windows 自带的 `csc`（兼容 C# 5）：

```bat
"%SystemRoot%\Microsoft.NET\Framework64\v4.0.30319\csc.exe" /nologo /optimize+ /t:winexe /out:VoicePaste.exe VoicePaste.cs
```

> `csc.exe` 不在 PATH 里，直接敲 `csc` 会提示「无法识别」。

## 常见问题

- **没有捕获到文字**：确认 `voice_trigger_hotkey` 与微信输入法实际热键一致；
  微信语音是否已登录/可用；可开 `debug=true` 看日志。
- **语音文字跑到 Windows 搜索框里 / 一说话开始菜单就弹起来**：这是 `Win+Alt` 的副作用，
  程序已默认开启 `close_start_menu`：说话期间检测到「开始菜单/搜索」会立即关闭并把焦点
  拉回捕获框，日志里会出现「检测到 Windows 开始菜单/搜索（…），正在关闭并把焦点拉回捕获框」。
  如果仍然偶发，可把 `debug=true` 打开，把 `voicepaste.log` 发出来（里面会记录前台窗口变化）。
  最彻底的办法是把微信输入法的语音快捷键换成不带 Win 的组合（如 `Ctrl+Alt`），conf 两行同步改。
- **终端里仍重复**：说明文字没有进入捕获框，通常是焦点没切过去或被其他输入法/程序抢占，
  查看 `voicepaste.log` 中的「开始说话 / 捕获到文字长度」记录。
- **热键无反应**：程序会自动检测并重装被系统卸载的键盘钩子（日志里会出现
  「键盘钩子无响应…自动重新安装」）。如果仍然无效，检查托盘里程序是否在运行；
  另外以管理员权限运行的窗口可能收不到普通权限进程的按键，遇到时用相同权限运行本程序。
- **微信语音直接接管、没有粘贴**：先看 `voicepaste.log` 里有没有「开始说话」。
  没有的话说明热键没被程序接住（钩子问题或热键不一致）；有的话看后续是否
  「捕获到文字」，没有则是微信语音没真正开始或没识别出内容。
- **退出**：右键托盘图标 →「退出 VoicePaste」。
